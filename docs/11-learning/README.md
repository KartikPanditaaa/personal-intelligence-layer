## The hardest problem in the repository

Two commitments sit in tension and the sources do not reconcile them:

- The product should make the user more capable over time.
- The product should be useful enough that people pay for it and keep using it.

A tool that genuinely reduces a user's need for it has an unusual retention
profile. [Glossary](../00-company/29-glossary-and-definitions.md) defines
co-evolution as "AI and user improve together", which is the proposed
resolution, but it is an assertion rather than an argument.

This is also where [Anti-Goals](../00-company/ANTI_GOALS.md) has the most
force: making users dependent on AI is explicitly excluded.

## What belongs here when it exists

- What growth means concretely, and how it is observed
- The confirmation loop by which the user validates what the system learned
- User-controlled profile evolution
- Measuring capability rather than usage
- Guarding against dependence in specific features
